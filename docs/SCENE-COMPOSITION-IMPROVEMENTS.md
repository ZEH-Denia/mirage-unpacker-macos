# 通用场景组合改进记录

日期：2026-11-06。范围仅限「仅导出图片」模式中的实验性静态场景组合，不含发布、更新或版本号变更。

## 验证方式与边界

- 真实素材：对本机 Mirage 工坊内容中**带 `scene.pkg` 的 27 个真实场景**做只读结构普查；其中 5 个结构不同的场景做了渲染前后对照（改动前的 1.8.0 源码在独立 git worktree 中重建为对照二进制，同一命令、同一目录对照）。素材与产物都不进仓库，私有证据在 `app/.build/` 下（被 Git 忽略）。
- **真实运行参考（本轮重做）**：Mirage 应用自带离线渲染器 `Contents/Resources/Renderers/SceneBaker` 与引擎资源 `assets/`，在隔离目录离屏渲染。参考帧取引擎**无损帧转储**（`SCENERENDERER_DUMP_FRAME` 直接写 PPM(P6)），不再经 H.264/MP4 中转再抽帧；视图按场景画布推导（`scale = min(4, 4096/max(w,h))`，与 PKD 输出同规则），奇数维度按引擎要求 +1 后裁掉 1 列/行，不缩放（sidecar 记 `parity_adjusted`）。每张参考旁都有 `<png>.request.json` 与 `<png>.log`：输入包/`scene.json` 哈希、画布与视图、完整请求参数、帧号口径、种子/属性/fillMode/音频、引擎与工具 SHA、返回码与原始日志。引擎仓库 `laobamac/MirageWallpaper`（GPL-3.0）公开，可作为格式语义依据。
- 帧号口径：转储的是引擎渲染循环的**第一帧**（`warmup=0`，请求时间 t=0）；不是“解码 MP4 第 0 帧”。实测 `SCENERENDERER_DUMP_FRAME_AT` 在 SceneBaker 下不改变结果（恒为首帧）；MP4 路径只用于交叉核对编码/色彩误差（25 张参考上“无损 vs 同帧 MP4 解码”平均差 1.19–3.32）。**仍不等于完整播放器**：脚本、音频响应、动态效果随时间变化，本参考只代表首帧的默认状态。
- 一致性依据因此是「引擎离屏参考帧 + 消融测量 + 格式语义/引擎源码 + 合成像素回归」，不宣称与播放器逐像素一致。
- 单位语义依据：官方脚本参考写明 `ILayer.angles` 为**角度制**；可检查的开源场景渲染实现注明静态 `scene.json` 的 angles 已是**弧度**，只在脚本 API 边界换算。
- 本机统计（可复核）：27 个场景共 **93 个对象带 `angles`**，其中 86 个是静态字符串、7 个是绑定对象。静态值里 |z| 最大 3.1253（< π），±1.57080（= ±π/2）出现 3 次，文本对象的 0.06981 / 0.01746 精确对应 4° / 1°。

## 1. 静态角度按弧度处理

- **现象**：带静态旋转的图层几乎不旋转（把 π/2 当成 1.57°）。
- **原因**：`scene.json` 的 `angles` 以弧度保存，原实现乘了 π/180 当作角度制。
- **改进**：图层与父节点的 Z 旋转直接按弧度应用；绕 X/Y 的旋转仍回退。
- **真实样本验证**：本机 27 个场景里，非零旋转只出现在粒子、文本与引擎内建层上，**没有一个普通图片层带旋转**，所以真实样本只能证明「不改变既有输出」：目标场景改动前后输出逐字节相同，另两个此前可渲染的场景也逐字节相同（哈希见私有证据）。弧度语义本身由官方脚本参考、独立实现的说明与本机统计支撑，并由合成像素回归（45° = 0.78540 与 0° 对照）固定。
- **仍不支持**：绕 X/Y 轴旋转、`attachment` 骨骼锚点。

## 2. 绑定属性改用保存的静态默认值

- **现象**：场景里只要有一处脚本或动画绑定的属性，整张预览直接失败。
- **原因**：绑定字段被整体当作未知结构拒绝。这些字段都带作者保存的 `value`；可检查实现的 `CImage` 也是直接读 `alpha/color/origin/scale/angles/visible` 的 `value`。
- **改进**：`origin`/`scale`/`angles`/`alpha`/`color`/`visible`/`brightness` 统一解析 `value`；缺少可用 `value` 才回退。脚本与动画不执行，报告里分别统计「脚本/动画绑定按静态默认值」和「条件绑定未求值」。绑定 `angles` 的保存值同样是弧度（本机样本最大 1.98603）。
- **真实样本验证**：
  - 3840×2160 / 15 对象场景：两层脚本绑定 `angles`（保存值为 `0 0 0`）导致整张失败，现在可渲染并端到端导出；另有用户属性绑定的 `visible`。
  - 2560×1440 / 31 对象场景：父层脚本绑定 `origin`、两层脚本绑定 `color`、一层动画绑定 `alpha`、一层条件型用户属性 `visible`，此前整张失败，现在可渲染并端到端导出，报告中「2 处脚本/动画绑定按静态默认值」「1 处条件绑定未求值」「2 个纯色层因混合模式未支持而跳过」。
  - 目标场景（3840×2160 / 28 对象）的绑定只落在被跳过的内建层、一个粒子与文本对象上，因此它的输出不受本项影响——这也是它与 1.8.0 输出逐字节相同的原因之一。
- **仍不支持**：脚本/动画逐帧求值；条件型用户属性（`user.condition`）不参与判断，只取保存值，报告会计数提示。

## 3. 旧版百分比不透明度

- **现象**：`alpha` 大于 1 的场景被拒绝。
- **原因**：旧版 JSON 用 0–100 百分比。可检查实现在读取时把 `> 1` 的值除以 100 并夹到 0…1；本实现只接受能归一化到 0…1 的数值，归一化后仍越界（例如 150）、或 `alpha` 是布尔值时回退。
- **改进**：`1 < alpha ≤ 100` 视为百分比除以 100；其余越界值回退。
- **真实样本验证**：本机 27 个场景没有出现百分比 alpha，保留兼容路径；合成像素回归验证 `alpha = 50` 与 `0.5` 结果一致，并固定 `150` 与布尔值回退。

## 4. 图层色调（color）

- **现象**：非白色 `color` 的图层导致整张预览失败。
- **原因**：原实现只接受白色；`color` 在格式里是 RGB 色调，作为材质常量传给着色器。
- **改进**：按 RGB 乘法作用于图层像素（预乘 alpha 下只乘 RGB，不改变透明度），报告色调图层数；`colorBlendMode` 变体语义未确认，遇到仍回退。
- **真实样本验证**：2560×1440 场景有两层分别用 30% 灰与脚本绑定的红色，现可渲染并计数；合成回归同时覆盖普通层与 puppet 网格的色调像素。

## 5. 不透明度与色调是逐层属性

- **现象**：已发布版本遇到父层 `alpha ≠ 1` 会整体放弃预览。本轮曾按「父子相乘」处理，经与可检查实现核对后改为逐层语义——相乘会错误隐藏子层。
- **原因与结论**：可检查实现的 `CImage::getAlpha()` / `getColor()` 只读取对象自身的 `value`，父层只提供变换。因此不透明度与色调既不拒绝、也不沿父链相乘；父链只用于变换与可见性判断。
- **真实样本验证**：合成像素回归固定「父层 0.5 / 0 都不影响子层」与「自身 alpha 为 0 不绘制」。真实样本中一个 `alpha = 0` 的分组容器（纯色底、`disablepropagation = true`）有 4 个直接子层：2 个普通图片子层照常绘制，另 2 个内建纯色子层按内建层跳过——与报告里的计数一致。
- **仍不支持**：`disablepropagation` 未处理（它在真实场景里几乎每个对象都出现，属于默认标志，不能作为拒绝条件）；父层可见性以外的分组语义未按播放器验证。

## 6. 图层尺寸与未确认外观属性

- **尺寸**：对象 `size` 优先，缺失时用纹理像素尺寸。模型 JSON 自带的 `width`/`height` 在两种可检查实现里的优先顺序互相矛盾，本机仅 2 个真实对象带该字段且与 `size` 相同，因此**保持既有行为**、不采用模型尺寸优先；合成回归固定「对象 size 优先」。
- **未确认外观属性一律回退**，不再静默忽略：`brightness ≠ 1`、`reflected`、`perspective`、非空 `attachment`。这些在本机真实样本的绘制层上都没有出现（`brightness` 只出现在文本对象上），所以恢复回退不会损失真实样本覆盖，但能防止「成功但画面错误」。合成回归逐项固定它们必须回退且保留旧结果。
- **仍不支持**：颜色混合模式、镜像、透视、骨骼锚点、亮度（>1 或 <1 都不是线性还原）。

## 目标真实场景诊断

对象 28 个：22 个图片对象（其中 8 个引用包内不存在的引擎内建模型，14 个可绘制）、3 个文本、2 个粒子、1 个音频。

- **层序**：按 `objects` 数组顺序绘制（画家算法）。14 个可绘制层与该顺序一致，背景层在最前。
- **坐标**：画布 3840×2160，可绘制层均为画布坐标系下的中心点 + 尺寸，无旋转（该场景的旋转值只在粒子与文本上）。
- **裁剪**：本场景 14 个模型描述符中 13 个带非零 `cropoffset`。扩大到全部样本：27 个场景共 121 个图片描述符，其中 45 个带 `cropoffset`；5 个对照场景合计 63 个可绘制层描述符（实际绘制 62 层，1 层自身 `alpha = 0`），它们的纹理像素尺寸与对象 `size` 全部一致。因此不再叠加 `cropoffset` 不会移动或缩放图层——这是本轮对裁剪问题的实际诊断结论。
- **不透明度**：4 个对象带浮点 `alpha`，全部是 0.0，且都在被跳过的内建层链上。
- **颜色**：绘制层没有 `color`（只有文本与内建纯色层有）。
- **父链**：10 个对象带 `parent`：7 个指向内建 `solidlayer`/`composelayer`，3 个指向粒子或文本对象；可绘制层本身不挂父链。
- **用户属性**：3 个 `user` 绑定（音频响应、雨夜、时间显示），分别落在被跳过的内建 `solidlayer`、一个粒子对象与一个文本对象上，都不在可绘制图片层上。
- **与播放器画面的具体差异**：静态预览缺少文本/时钟、2 个粒子系统与 5 个绘制层的图层效果（呼吸、摇摆、水波、脉冲、眨眼等动态效果）。内建层共 8 个：4 个 `solidlayer` 的 alpha 为 0、4 个 `composelayer` 是容器，因此不贡献像素。量化差异见第 9 节（引擎离屏参考帧）。

## 8. 内建纯色层（solidlayer）与容器（composelayer）

- **依据**：引擎资源 `assets/models/util/solidlayer.json` → `materials/util/solidlayer.json` → 着色器 `flat`，`shaders/flat.frag` 为 `gl_FragColor = vec4(g_Color, g_Alpha)`；`composelayer` 的材质采样 `_rt_FullFrameBuffer`（全屏 copy），模型 JSON 标 `"passthrough": true`，本身不产生内容。
- **改进**：`models/util/solidlayer*`（以及包内描述符 `"solidlayer": true`）按对象 `color` 与 `alpha` 绘制纯色矩形；`composelayer*/projectlayer/fullscreenlayer` 作为容器只绘制子层、自身不计入绘制；未知 util 模型仍跳过并计数。
- **真实样本与回归**：合成 `solid` 场景的解析预期为「红色 50% 叠加灰底 = (160,32,32)」；语义回归还覆盖引擎内建 solidlayer、包内 solidlayer 描述符与 composelayer 容器不计像素。
- **对目标场景的影响**：4 个 solidlayer 的 `alpha` 都是 0（不绘制），4 个 composelayer 是容器；引擎消融显示 `no_builtin` 的差为 **0.00**，即内建层在 t=0 不贡献像素，目标输出与 1.8.0 **逐字节相同**（`057e550b…`）。这是「有依据的支持 + 对目标无误伤」，不是"改了没效果"。注：该“逐字节相同”属于本批组合改进与 1.8.0 的对照；随后主渲染的 puppet 蒙皮改动使目标输出变为 `cd6b0c3a…`，两者不矛盾（见第 9 节）。
- **对其他真实场景的效果**：两个此前整体失败、本轮可组合的场景因此改变了纯色层处理——3840×2160 场景报告「2 个纯色层因混合模式未支持而跳过」，2560×1440 场景绘制 1 个内建纯色层并跳过 2 个混合模式纯色层。与**本次无损参考**对比：3840×2160 场景平均差 **2.50**（>16 像素 3.12%）。旧的“29.16 → 4.22（20.28% → 5.18%）”是经 MP4 中转参考的测量，含约 2.4 的中介误差，保留为历史记录，不再与本次数值混用。

## 9. 真实运行参考与目标差异

### 9.1 本轮参考与消融的做法（可复算）

- 引擎参考改为**无损帧转储**：给 `SceneBaker` 设 `SCENERENDERER_DUMP_FRAME`，引擎把结果图像写成 PPM(P6, 8bit RGB)，不经 MP4/H.264，也没有“解码第 0 帧”这一步。
- 视图由**场景画布**推导（与 PKD 相同规则 `scale = min(4, 4096/max(w,h))`，宽高四舍五入），不再把所有场景压成 4096×2304。引擎请求要求偶数尺寸，7 个场景的奇数维度只 +1 后裁掉 1 列/行（**不缩放**，sidecar 记为 `parity_adjusted`）。
- 每张参考旁都有 `<png>.request.json` 与 `<png>.log`，含：输入包与 `scene.json` 哈希、画布/视图、完整请求（fps/duration/warmup/speed/seed/fillMode/properties/audio）、帧号口径、引擎与工具 SHA、返回码及原始 stdout/stderr。
- 帧号口径：转储的是引擎渲染循环的**第一帧**（`warmup=0`，请求时间 t=0），不是“解码 MP4 第 0 帧”。实测 `SCENERENDERER_DUMP_FRAME_AT` 在 SceneBaker 下不改变结果（恒为首帧）；MP4 只用于交叉核对编码与色彩转换误差。
- 目标场景消融与 PKD 同变体对照在 `app/.build/ablate-rerun-20261107-093025/`（`analysis.json` / `analysis.md`），变体仍由 `pkg_ablate.py` 生成且先做“重写与原包逐字节相同”自校验；基线与矩阵参考哈希一致，说明离屏参考可复现。
- 待测二进制：矩阵的全部 27 次渲染使用证据目录内**固定副本** `bin/pkd-selftest`，sha256 `bb7d06d4…`；副本在运行前后 inode/哈希不变。原始 `app/.build/debug/pkd-selftest` 在本轮期间被并发就地重建（内容哈希经历 `dd99…`→`5493…`→`bb7d…`→`115cc…`），但对同一组 27 个解包目录重渲染得到 25 个成功场景**逐字节相同**的输出（`app/.build/matrix-final2-20261107-094017/logs/cross-build-check-115cc385.json`），因此矩阵统计对这几份构建一致。`SceneBaker` sha256 `9a0d0d76…`、`repkg` sha256 `7f1d0b24…`、Mirage 1.1.5。主渲染源码仍可能变化，不把一次快照当永久结论。
