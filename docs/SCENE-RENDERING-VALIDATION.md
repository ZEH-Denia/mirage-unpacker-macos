# 场景静态组合验证

## 判断规则

图片导出会结合包目录与 `scene.json` 检查实际图层；无法读取包目录时仍尝试检查场景。多图层即使共享一张纹理也会尝试组合。只有一个普通图片对象、无特效且画布覆盖和图片比例均一致时，沿用普通导出。未知或不支持的结构保留原始图片，并报告静态预览限制。

当前支持普通图片和 puppet 的基本二维位置、旋转、缩放、层顺序、整层透明度、裁剪图层，以及受限的多级二维父子变换。`cropoffset` 的处理依据本机真实素材的坐标关系和对开源场景渲染实现的检查：位置以场景对象 origin 为准，不再次叠加裁剪偏移；这属于针对已检查格式的实现判断，不代表覆盖所有格式变体。参考：[Wallpaper Engine 图层说明](https://docs.wallpaperengine.io/en/scene/assets/overview.html)、[开源场景渲染器](https://github.com/waywallen/open-wallpaper-engine)。

用户属性绑定采用场景文件中的默认值，不等同于读取用户在播放器里设置的实际值；脚本和动画绑定、未知材质、3D 变换及复杂父节点透明度仍会回退。输出为实验性静态图，不承诺与动态播放器逐像素一致。

## 本机验证

- 目标真实场景：正式应用经选择、导出和结果浏览器打开，生成 4096×2304 静态预览。重复导出产生独立名称，保留已有文件，浏览器将最新预览置顶并显示限制提示。
- 另一个真实模型场景、一个真实 X-Ray 场景及三个其他真实场景已用于解包、图片冲突或静态组合检查；真实素材及其产物不加入仓库。
- 合成场景覆盖裁剪偏移、普通层、多个 puppet、二维父子平移/旋转/多级缩放、层透明度、用户属性默认值、隐藏图层、循环父节点、脚本绑定与失败时保留旧结果。
- 单纹理多次引用的合成包用于验证预检不会仅凭纹理数跳过组合；模拟包信息读取失败时同样验证会继续检查场景。
- RePKG 动画纹理覆盖 PNG 编码和原始像素编码：验证 GIF 格式、两帧像素、帧时长及尺寸；超大 PNG 图集应拒绝并保留原 TEX。实际场景中的五帧 PNG 动画已验证成功转换。
- 使用旧版和修改后的引擎分别解包另一份真实场景，43 个输出文件路径及 SHA-256 全部一致。
- 真实目标场景在正式应用中多次导出，保留两份模式下当次已有文件的名称、大小及修改时间保持不变；最终引擎不再报告纹理转换错误。备份当前 53 个输出文件后重启应用，短期及稍后复核的文件列表和 SHA-256 均不变。
- 另行检查单张普通图片铺满画布时无需组合，图片比例与画布不同时会尝试组合；图片重复规则、结果浏览器中的重复预览排序以及普通队列回归均有自动检查。

早期两个测试快照之间观察到 25 个带编号的历史副本消失；发生时间和原因未知，没有证据证明由应用删除。后续受控导出与重启未复现，当前输出有独立备份；不能据此推断早期缺失副本的去向。

## 不足

真实场景运行画面会受时间、用户参数、输入、粒子和材质影响；本轮没有使用完整播放器运行时逐帧对照，也没有证明所有 Wallpaper Engine 场景结构均可还原。结果中的静态预览提示应保留。
